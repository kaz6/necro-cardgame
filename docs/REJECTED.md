# 2026-08-11 追記（CG-005・能力持ち4種の裁定）

**c05 の後列が埋まっているとき、前列の空き枠へ退避させる**
c05 が守られる場所を得るのは「後列が空いていた」という盤面条件の報酬である。前列に逃がすと
倒された直後に守り手として復帰し、倒された罰が消える。
→ **死んだ案**。不発（通常どおり相手の墓地へ）を採用。切り替えは `rules.abilities.deathRetreatNoRoom` に残してある

**c05 の後列が埋まっているとき、後列のカードを押しのけて入る**
押しのけられた自分のカードが相手の墓地へ行くことになり、味方を1枚献上する自傷能力になる。
「倒されても粘る」という能力の意図と逆を向く。
→ **死んだ案**

**c07 を「自分から攻撃して倒したとき」限定にする**
守りに回ったときに何も起きないカードになり、4/2 という受けに強い数値と噛み合わない。
テキストも「倒したとき」であって「攻撃して倒したとき」ではない。
→ **死んだ案**。反撃時も発動を採用。切り替えは `rules.abilities.killTriggerOnCounterattack` に残してある

**c08 の呪いを加算せず、1枚ずつ順次消費する（毎回 +1）**
1枚目が消費された後の召喚は2枚目にとって「最初の1回」ではなくなるため、
2枚目が事実上腐る。デッキに2枚入れる意味が消える。
→ **死んだ案**。加算・同時消費を採用。切り替えは `rules.abilities.curseStacking` に残してある

**c08 を2枚にした分、デッキを29枚にする**
前後比較でデッキ枚数が動くと、盤面埋まり率や決着ターンの差が能力由来か枚数由来か分離できない。
→ **保留（種）**。デッキ枚数自体は未確定項目なので、枚数を動かす検証をするときに正面から扱う

# 2026-08-11 追記（CG-006・評価関数ベースの CPU）

**CPU の評価の重みを `data/cards.json` に入れる**
cards.json はゲームの正本（ルールと数値）で、CPU を強くするための調整は仕様ではない。
同じファイルに混ぜると「バランス調整が JSON の編集だけで完結する」の JSON がどちらを指すのか
読めなくなり、AI 向けの調整が仕様の差分に紛れ込む。
→ **死んだ案**。`data/ai.json` に分離を採用

**評価で相手の盤面を自分と等倍（1.00）に見る**
一見もっとも素直だが、**相打ちの損得がちょうど 0 になる**ため、CPU 同士が盤面をにらんだまま
一手も動かなくなる。ネクロマンサーは相手の場が空でないと殴れないので、試合が決着しない。
→ **死んだ案**。1.06 倍を採用（`data/ai.json` の `foeUnitScale`）。
★ これは**ゲームの仕様ではなく AI の癖**なので、仕様側の数値と混同しないこと

**CPU に完全な state を渡す（filterStateFor を通さない）**
実装は短くなるが、権威サーバ側でそのまま動かせなくなる。サーバがクライアントへ返すのは
視点フィルタ済みの state だけなので、サーバ専用の別実装を持つことになる。
相手の手札を見て指す CPU は、対戦相手としても正しくない。
→ **死んだ案**。engine の外側に置き、必ず `filterStateFor` を通す
