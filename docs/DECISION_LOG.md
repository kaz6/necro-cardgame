# 2026-08-11｜ドロー＝2枚めくり1枚選択、残り1枚は自分の墓地へ

自分のデッキから2枚めくり、1枚を選んで手札に加える。選ばなかった1枚は自分の墓地へ落ちる。

ドローそのものを選択の場にする。同時に、毎ターン自分のカードが墓地に積まれていく。

# 2026-08-11｜盤面あり（Hearthstone ライク）／ステータス2値／体力は回復しない

- 盤面を持つ。カードは盤面のスロットに出す。
- ステータスは2値のみ。**攻撃 / 体力**。
- **体力は回復しない。** 受けたダメージは残り続ける。

削れた体力が戻らないことで、盤面上のカードにも「消耗の履歴」が残る。

- 各プレイヤー1枚。
- 常時場に出ており、公開。
- 手札に戻す・場から出す等の出し入れは不可。
- **倒されたら敗北。**

勝利条件をネクロマンサー撃破に固定する。

# 2026-08-11｜墓地は分離。相手の墓地からのみ蘇生可能

- 墓地は各プレイヤーで分離して管理する。
- 蘇生できるのは**相手の墓地からのみ**。自分の墓地からは蘇生できない。
- 蘇生は**ノーコスト**、**1ターンに1枚**まで。
- 代償として、**自分のデッキ上から1枚を自分の墓地へ落とす**。

蘇生の対価をマナではなく「自分の残り時間」で支払わせる。

# 2026-08-11｜呪いは墓地常在型

呪いは**墓地にある間に効果を発揮する**。

自分の墓地に呪いがある間、**相手の蘇生に追加コスト1枚を課す**
（相手は蘇生時に、通常の代償に加えてもう1枚デッキから墓地へ落とす）。

奪われる側が仕掛ける防御的な札として設計する。

# 2026-08-11｜オンライン対戦は権威サーバ型。ロックステップ／ロールバックは不採用

将来のオンライン対戦は**権威サーバ型（authoritative server）**で実装する。

- クライアントは action オブジェクトのみを送信する。
- サーバが唯一の state を保持し、`filterStateFor(state, playerId)` を通した
  視点別 state だけを各クライアントへ返す。

**ロックステップ／ロールバック方式は採用しない。**
理由: 本作は手札・デッキという隠し情報を持つ。これらの方式は全クライアントが
完全な state を保持することを前提とするため、クライアント側に相手の手札・
デッキが存在してしまい、チート耐性の要件を満たせない。

この判断が engine の実装制約（純粋関数・action によるシリアライズ・
シード管理された乱数・視点フィルタ）の根拠である。詳細は `CLAUDE.md` および
`ARCHITECTURE_PRINCIPLES.md` を参照。
