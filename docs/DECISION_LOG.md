# 2026-08-11｜ルール骨格の確定（9項）

> ⚠️ この9項のうち **1（2枚ドラフト）・2（持ち駒ゾーン）・4（マナ制）・7の「デッキ切れ敗北」は
> 後の判断で撤回されている。** また **6（相手の墓地からのみ蘇生）は「訂正：召喚元は『自分の墓地』」で、
> 9（呪いの効果）は「呪いカードの効果は接続先を失っている」で改訂されている。**
> 撤回・改訂の内容は下方の各エントリを参照。歴史として残す。

1. **ドロー＝自分のデッキから2枚めくり1枚選択、残り1枚は自分の墓地へ。**
   理由: 1枚選ぶ＝1枚差し出すの等価交換になる。3枚だと毎ターン2枚を供給することになり過剰。判断疲れも半減。
   → **撤回済み**（毎ターン2枚ドローへ）
2. **倒したカードは公開の持ち駒ゾーンへ。デッキには混ぜない。**
   理由: 将棋の持ち駒は即打てる。デッキに混ぜると再登場までラグが出て因果が切れる。公開ゾーンなら「渡してしまったカード」が常に視界にあり、圧が持続する。
   → **撤回済み**（自分の墓地へ）
3. **盤面あり（Hearthstone ライク）。ステータス2値＝攻撃力／体力、体力は回復しない。**
   理由: 「奪い返す逆転」には同じカードが何度も盤上に戻る必要があり、「あのカードを奪えば一気に逆転できる」にはターゲット選択が要る。1値だと盤面が毎ターンリセットされ、判断軸の変化が発生する前に決着する。
4. **マナあり（固定増加制）。**
   理由: 同一ターンに複数枚を組み合わせられ＝即興コンボが発生する。奪ったカードを打つのにもマナが要るため、持ち駒が一気に雪崩れるのを防ぐ弁になる。
   → **撤回済み**（ピッチコスト制へ）
5. **ネクロマンサー: 各プレイヤー1枚。常時場・公開・出し入れ不可。倒されたら敗北。**
   理由: 増えた選択肢が向かう先（将棋の詰みに相当する離散的ゴール）が必要。これがないと選択肢の増加が試合の膨張になる。出し入れは実装と判断が重くなるため不可で固定。
6. **墓地は分離。相手の墓地からのみ蘇生可能。ノーコスト・1ターン1枚、代償は自分のデッキ上から1枚を自分の墓地へ落とす。**
   理由: 支払うのをマナではなく寿命にすることで、テンポの気持ちよさを残しながらジレンマにできる。落とした1枚は相手も使える墓地に積まれるため、蘇生のたびに相手の選択肢を増やす。ネクロマンサーが自分の生命力を削って死者を起こす絵と一致。
7. **デッキ30枚。初手は先攻6枚／後攻7枚。**
   理由: デッキ枚数＝残り時間。毎ターン2枚確実に減るため、10〜12ターンで尽きる。この構造により「デッキ圧縮＝寿命を削る博打」に反転する。先後攻補正はカード差で行う（コイン等の追加リソースは入れない）。
   → デッキ切れ敗北は**撤回済み**
8. **カード8種。うち4種が能力持ち（呪い1種＋有効効果3種）。呪いはデッキに2枚。**
   理由: 数値だけだと「毎ターン一番強いカードを出す」で終わり、判断軸が1本になる。能力の役割は「数値が低いのに奪う価値がある」状態を作ることに限定する。
9. **呪いカードは墓地常在型。自分の墓地にある間、相手の蘇生に追加コスト1枚を課す。**
   理由: 回避不能であることが重要。「自爆特攻するか捨てる」がそのまま正しいプレイになり、デメリットカードが攻撃手段に反転する。墓地分離と噛み合い、押し付け合いが墓地の中で起きる。

# 2026-08-11｜ピッチコスト制の採用（マナ制の撤回）

> ※ 召喚元は「2026-08-11｜訂正：召喚元は『自分の墓地』」で改訂されている。
> 正しくは**手札または自分の墓地から**。

カードを場に出すには手札からカードを捨てる。捨てたカードのコスト合計が支払いポイントになり、
その範囲で手札または相手の墓地から出せる。1:1変換。

理由: 核がコスト支払いのレベルで再現される。出すこと自体が相手に死体を渡す行為になり、
戦闘で奪われる前からジレンマが動き出す。マナを消したことで Hearthstone 的な骨格からも離れられる。

「同等コストのカード1枚を捨てる」案は却下。コスト3を出すのもコスト1を出すのも消費1枚となり、
常に高コストを出すのが正解になって低コストカードが存在意義を失うため。

# 2026-08-11｜2枚ドラフトの廃止（毎ターン2枚ドローへ）

理由: ドラフトの捨て札は墓地を肥やすために入れたものだったが、その役割をピッチコストが完全に代替した。
残るのは判断コストだけになる。ピッチという毎ターン必ず起きる濃い判断がある以上、ドローは単純でよい。

**ただし「ドラフト」という機構そのものは死んでいない。** ターン内ドローとしては廃止だが、
別枠（カードプール→デッキ作成の工程）での復活を想定する。`REJECTED.md` を参照。

# 2026-08-11｜デッキ切れ敗北の撤回

理由: ピッチコストで手札消費が激増したため、30枚では時計として速すぎる。
また「デッキ圧縮＝自殺」という圧縮対策としての役割も不要になった。
手札の枚数そのものが弾薬になったため、誰も薄いデッキを作らない。
デッキ枚数は純粋に試合の長さの調整弁に戻す。

# 2026-08-11｜持ち駒ゾーンの廃止。倒したカードは自分の墓地へ

理由3点。

1. ゾーンが3つ（自分の墓地・相手の墓地・持ち駒ゾーン）あり、それぞれ召喚条件が違って参照先が多すぎた
2. 「蘇生できるのは相手の墓地からのみ」と矛盾していた。同じ奪ったカードが2つの異なる法則で動いていた
3. 最大の理由: 倒したカードが即座に使えなくなることが snowball の制動装置になる。
   倒した瞬間に得るのは資源の権利であって盤面の駒ではない。しかも自分の墓地のカードは相手が蘇生できるため、
   奪ったものが奪い返される。「奪い奪い返し合う」が成立する

「倒したカードを即座に自分の場へ置き直す」案は基本ルールとしては却下
（倒す→即再展開→また倒すでリードした側が一方的に加速するため）。固有効果として残す。

# 2026-08-11｜墓地の定義を一本化

**自分の手を離れたカードは、すべて相手の資源になる。例外なし。**

自分の墓地に入るのは、①自分が倒した相手のカード ②相手がコスト支払いで捨てたカード の2つだけ。
自分のカードは捨てても倒されても必ず相手の墓地へ行く。

理由: この定義により「自分の墓地からは蘇生できない」という制限ルールが不要になる。
構造上、自分のカードがそこに存在しないため。ルールが1つ減り、法則が1本になった。

# 2026-08-11｜盤面は 3列 × 2段 の6枠。前列が残る間、同列の後列は攻撃されない

攻撃は前列・後列どちらからも可能。配置換えも可能。

理由: 前後列は Hearthstone から離れる方向で望ましい。枠数を6に絞ったのは、
固定枠が埋まらないと前後列の判断が発生しないため。
同時に、この6枠が小型量産に対する唯一の歯止めになる（追加ルールなしで制動がかかる）。

# 2026-08-11｜墓地の総コストを表示する（効果は持たせない）

各プレイヤーの墓地のコスト合計を常時表示する。プロトでは表示のみ。

理由: 在庫としての墓地は使えば減るので「肥える」感覚が出ない。
総コストを状態量にすることで墓地が初めて育つものになり、しかも肥やしているのは相手側の行動である。
核が最後の一箇所まで貫通する。
ただし何点で何が起きるべきかを机上で決めると数字に合わせた効果になるため、まず観測する。

# 2026-08-11｜連続攻撃系の効果は単体で入れない

連続攻撃（1体ずつ複数回攻撃）は倒した数だけ持ち駒が増えるため snowball を強める。
入れる場合は「このカードが倒したカードは自分の墓地ではなく相手の墓地へ送られる」等の制限とセットにする。
強制攻撃系（相手の行動を縛るだけで盤面資産が増えない）のほうが副作用が小さい。

# 2026-08-11｜世界観の帰属を決定。カスケード後のif世界に属させる

> ※ 表記は「2026-08-11｜訂正：世界観の表記を緩める」で改訂されている。
> 時系列上の前後関係を断定しないこと。

表世界が魔素に飽和して魔界化した後の世界。剪定／カスケード侵略（凍結中）と同じif枝に属する。

理由: 正史の世界との衝突2件が、これで同時に解消される。

1. 魔法は魔導図書館へのアクセス権モデルで、発行主体は図書館、教育の重点は倫理観。
   死者を掘り起こして使役する術者はこの体系のどこにも入らない。
   認可体系が崩壊した後なら、体系外にいることに説明が要らない
2. この世界の埋葬作法は「墓守の樹の下に埋め、樹に名を刻む」。掘り起こして使役するのは直接的な冒涜だが、
   **冒涜が可能なのは、冒涜を咎める社会がもうないから**である。
   作家性の一極（狂気・不条理・ダーク）に、既存設定をそのまま使って接続できる

- **正史の世界（現在時制）に属させる** → ネクロマンサーを魔法使い（怪異レベル）扱いにするしかなく、

- **独立世界（共有世界に属さない）** → 設定が味方にならない。
  if枝に属させれば、衝突がそのまま話の燃料に変わる

# 2026-08-11｜測定の記録規約：日時・HEAD・シードの3点を併記する

測定値には **実施日時・HEAD ハッシュ・シード** の3点を必ず併記する。
3点そろわない数値は「いつのものか不明」として扱い、判断の根拠にする前に測り直す。

理由: 本作の乱数は seeded RNG のみなので、**シードがあれば結果を完全に再現できる**。
HEAD がなければ checkout して測り直せない。日時だけでは、どのコードで測ったか特定できない。

★ **シードの遡及はしない。** 既存の測定値に後からシードは付けられないため、
規約に「次に測り直したときに付く」と明記した。ハッシュのない測定値は判断の根拠にしない。

★ **測定値の HEAD は、測定に使ったコードのハッシュでなければ意味がない。**
ハーネスを未コミットのまま測ると HEAD が測定対象を指さない。**先にコミットしてから測る。**

生成主体が Claude Code へ移る。**生成主体が移るものだけが反転する。**

★ これで「本企画は SESSION_STATE・CURRENT_SPEC とも Notion 正本」という同日の記述は、
**将来にわたって両方が同じ向きであることを意味しない**ことが確定した。向きは文書ごとに独立して決まる。

矛盾の原因: **遠征ギルドログの型をコピーした際、ページ名と宣言を向きの検証なしに持ち込んだ。**
その結果、Notion 側のページ名が「写し・閲覧用」、1行目が「正本はリポジトリの docs」となり、
指示と食い違ったまま残っていた。

★ **型を借りるときは、向きが同じかを先に確かめること。**

却下した案: **B（repo を正本にする）** → `REJECTED.md` に記載。

# 2026-08-11｜能力持ち4種（c05〜c08）の効果と、テキストに書かれていない部分の裁定

決定: 4種の効果テキストを確定し、**テキストに書かれていない部分は `data/cards.json` の
`rules.abilities` でフラグ化した。** engine にハードコードした解釈は1つもない。

前提: 4種とも **「自分の手を離れたカードは、すべて相手の資源になる」法則の内側で動く。**
法則に例外を作るカードは今回入れない。

## 効果テキスト（確定）

- **c05**: 倒されたとき、1/1 になって後列へ移動する
- **c06**: 場に出たとき、右の空き枠に 1/1 のトークンを出す
- **c07**: 相手のカードを倒したとき、相手のデッキの一番上1枚を自分の墓地へ送る
- **c08**: 呪い。このカードが相手の墓地にある間、相手が墓地から召喚する最初の1回に、
  支払いポイントを1多く必要とする

## テキストに書かれていなかった部分の裁定（4件）

**1. c05 の後列に空きがない場合 → 不発。通常どおり相手の墓地へ**（`deathRetreatNoRoom: "toGraveyard"`）

理由: c05 が守られる場所を得るのは「後列が空いていた」という盤面条件の報酬である。
前列に逃がすと、倒された直後に守り手として復帰してしまい、倒された罰が消える。
**押しのけ案は自分のカードを勝手に相手の墓地へ送ることになり、能力が自傷になる**ため採らない。

**2. c05 の退避先が複数あるとき → 同じ列の後列を優先し、埋まっていれば後列を左から**
（`deathRetreatSlotOrder: "sameColumnFirst"`）

理由: 「移動する」と読める最短の動きが同列の後退である。engine の決定性のため順序は必ず固定する。

★ **c05 が退避しても「倒された」事実は残る。** c07 の撃破時効果は退避したときも発動する。
c05 の能力は死の否定ではなく、**墓地へ行く経路の置き換え**である。

★ **墓地に入った時点で 1/1 の上書きは外れ、刷られた数値（1/2）に戻る。** 退避権も戻る。
「移動後に再度倒されたら通常どおり墓地へ」は**場に居る1回分**を指す。

**3. c07 は反撃で倒したときも発動する**（`killTriggerOnCounterattack: true`）

理由: テキストは「相手のカードを倒したとき」であって「攻撃して倒したとき」ではない。
攻撃時限定にすると、4/2 という**受けに強い数値**と効果が噛み合わなくなる。

**4. c08 が相手の墓地に複数あるときは加算し、その召喚でまとめて全部発動する**
（`curseStacking: "add"`）

理由: 呪いはそれぞれが独立に「最初の1回」を持つ。2枚あれば同じ召喚が両方にとっての
最初の1回になるので、+2 になり両方が同時に消費される。
**1枚ずつ順次消費する案は、1枚目が消費した後の召喚は2枚目にとって「最初」ではなくなるため、
2枚目が事実上腐る。**

## デッキ構成（呪い2枚投入にともなう調整）

c08 を 3→2 枚にし、**減らした1枚は c07 に回した（3→4 枚）。**

理由: c07・c08 はどちらもコスト4 なので、**デッキのコスト構成比が CG-001 の測定時と完全に同一に保たれる。**
前後比較でデッキ側の母数が動かないことを、能力の効果を読むことより優先した。
デッキを29枚にする案は、盤面埋まり率の差が能力由来か枚数由来か分離できなくなるため採らない。

## トークンの扱い

> ※ この節は「2026-08-11｜トークンは倒されると消滅する（CG-007）」で改訂されている。
> **倒されたトークンは相手の墓地へ行かず消滅する**（`tokens.list[].onDeath`）。

トークンは `data/cards.json` の `tokens` に定義を置いた。デッキには入らない。
持ち主は出した側で、倒されれば通常どおり相手の墓地へ行く。

★ **コストが0なので、相手の墓地に落ちたトークンは 0pt で召喚し直せる。**
これは「トークンのコストは0」という指示の直接の帰結であり、意図的に残している。
歯止めが要ると判断した場合は `tokens` の定義側で変える（engine は触らない）。

却下した案: 5件を `REJECTED.md` に記載。

## 計測

同一条件（シード 1000〜1999・1000戦・同じランダムAI）で前後比較した。
観測値は `docs/research/自動プレイ基礎統計_20260811_CG005.md`。
**盤面の平均埋まり率は 26.0% → 26.8%（+0.8pt）で、ほぼ動かなかった。**

# 2026-08-11｜CPU は engine の外側に置き、視点フィルタ済みの state だけを見る（CG-006）

決定: 評価関数ベースの CPU を **`js/ai.js`** に置く。engine には入れない。

- **`(state, playerId) => action` の純粋関数。** state を変更しない
- **乱数を使わない。** 同じ state からは常に同じ手が出る（seeded RNG すら使わない）
- **内部で必ず `filterStateFor(state, playerId)` を通す。** 相手の手札と両者のデッキは
  engine の視点フィルタが落とすので、**AI がそれらに触れようがない構造**になっている
- 候補手の評価には engine の `reduce` をそのまま使う。**AI 側にルールを書き写さない**
- 合法性は engine のヘルパ（`legalActions` / `canSummon`）に訊く
- 評価の重みは **`data/ai.json`**。`js/ai.js` に数値をベタ書きしない

理由: 権威サーバ型のオンライン対戦で、**サーバ側の CPU をそのまま動かせるようにするため。**
サーバがクライアントへ返すのは `filterStateFor` を通した state だけなので、
完全な state を必要とする CPU を書くと、サーバ専用の別実装を持つことになる。

★ **重みを `data/cards.json` に入れなかった理由。** cards.json はゲームの正本（ルールと数値）、
ai.json は**対戦相手の性格**である。CPU を強くするための調整が仕様の差分に混ざると、
「バランス調整が JSON の編集だけで完結する」の JSON がどちらを指すのか読めなくなる。

## 探索

**1手先だけを読む貪欲法。** 合法手を1つずつ `reduce` にかけ、評価が最も上がる手を選ぶ。
上がる手が無ければターンを終える。**強さは追求しない**（CG-006 の裁定どおり）。

召喚の候補は組み合わせ爆発するので、
①同じ cardId は1枚に畳む ②ピッチは「必要ptを満たす最小の組」に固定する、の2点で絞っている。
★ **ピッチを最小にすることは、相手の墓地へ渡す資源を最小にすることでもある。**

## 相手の盤面価値に 1.06 倍をかけている理由

評価が完全に対称（1.00倍）だと、**相打ちの損得がちょうど 0 になる。**
すると CPU 同士が盤面をにらんだまま一手も動かなくなり、
**ネクロマンサーは相手の場が空でないと殴れない**ため試合が決着しない。
1 より少しだけ大きくすることで、**他に良い手が無いときだけ相打ちを選ぶ**。
有利トレードは元から大きく勝つので、優先順位は変わらない。

★ この倍率は**ゲームの仕様ではなく AI の癖**である。仕様側の数値と混同しないこと。

## 計測

`tools/simulate.js` の中身を `tools/harness.js` に切り出し、AI を差し替えられるようにした。
**ランダムAI の乱数の消費順は CG-001 / CG-005 から変えていない**ので、
同じシード帯を回せば当時の観測値がそのまま再現する（確認済み）。
観測値は `docs/research/CPU対戦比較_20260811_CG006.md`。

# 2026-08-11｜トークンは倒されると消滅する（CG-007）

決定: **倒されたトークンは相手の墓地へ送らず、その場で消滅する。**
CG-005 の「トークンのコストは0の直接の帰結として残す」を、歯止めを入れる側へ改訂した。

根拠: [トークンの消滅：前後比較](research/トークン消滅_前後比較_20260811_CG007.md)

## 理由

コスト0のため墓地から **0pt で再召喚**でき、CG-006 の CPU 同士1000戦では
**全召喚の 91.7%（259435 / 282897 回）がトークンの再召喚**になった。
トークン1枚が両者の墓地を往復し続けて盤面が空かないため、
**相手の場が空でないとネクロマンサーを殴れない**ルールと噛み合って決着条件が消え、
1000戦中150戦が未決着（ターン上限300）になった。
**ピッチを1枚も払わずに盤面を埋め続けられる手の存在自体が、ピッチコスト制の外側にある。**

## 一貫法則の例外ではない

「自分の手を離れたカードは相手の資源になる」の**例外ではない。**
トークンはカードとして手札に存在しないので、**そもそも手札を離れていない。**
法則の対象外として整理する。

## 実装（フラグの置き場所）

- `data/cards.json` の `tokens.list[].onDeath` に置いた。既定は `'vanish'`
- **engine は `defs[cardId].onDeath` を読むだけで、「トークンかどうか」では分岐しない。**
  カード定義側のフラグなので、将来ほかのカードにも同じ挙動を持たせられる
- **省略時・`'toGraveyard'` 指定時は CG-006 までの挙動**に戻る。
  セルフテストで両方の挙動を検査している
- 消滅したカードは `state.cards` からも落とす（どのゾーンにも属さないため）。
  iid の採番は単調増加なので決定性には影響しない
- ★ 相打ちで**倒した側が消滅する**場合があるため、撃破時効果（c07）の解決を防御した

|---|---|---|
| 盤面の平均埋まり率 | 67.4% | 28.3% |

| 平均決着ターン数 | 11.6 | 8.9 |

# 2026-08-11｜file:// から開けるようにする（CG-008）

## 症状

Windows で `index.html` をダブルクリックすると盤面が描画されない。

- `Access to script at 'file:///.../js/view.js' from origin 'null' has been blocked by CORS policy`
- `Failed to load resource: net::ERR_FAILED (js/view.js)`

原因は2つ。**どちらも file:// の origin が `null`（unique origin）になることによる。**

1. `<script type="module">` — ES モジュールは CORS 前提で取得されるので、file:// では常に失敗する
2. `fetch('./data/cards.json')` — 同じ理由で読めない

★ **サーバを立てれば直る、では要件を満たさない。** 作者はダブルクリックで開いて遊ぶ。

## 決定

**ES モジュールをやめ、素の `<script>` と即時関数（IIFE）で組む。**
データファイルは `.json` をやめ、**中身が素の JSON の `.js`** にする。

- `js/engine.js` / `js/ai.js` / `js/view.js` は全体を IIFE で包み、
  - ブラウザ … グローバル `NECRO_ENGINE` / `NECRO_AI_CPU` に入る
  - Node … `module.exports` で同じものを返す
- `data/cards.js` / `data/ai.js` は `var NECRO_CARDS =` ＋ 素の JSON ＋ `module.exports` の3層。
  **データの正本はこの1ファイルだけ。`.json` との二重管理はしない**
- `package.json` から `"type": "module"` を外す（CommonJS）。`tools/` も `require` に統一
- 読み込み順は `index.html` で固定（データ → engine → ai → view）

## 制約は1つも緩めていない

| 制約 | どう保ったか |
|---|---|
| engine は DOM を触らない | IIFE の引数 `root` に触るのは公開行だけ。ロジックは無改変 |
| Node 単体で実行できる | `node js/engine.js` 89件 / `node js/ai.js` 14件 すべて成功 |
| 数値を JS にベタ書きしない | データは `data/*.js` の JSON 部分のまま。engine からは無改変で読む |
| ビルド工程を増やさない | 生成物なし。置いてあるファイルがそのまま動く |

## なぜ他の案を採らなかったか

- **`.json` を残して `.js` を併産する（二重化）** … 生成工程が要る。手で同期すると必ずずれる。
  「JSON を1行直したのに盤面に反映されない」が起きる。→ REJECTED
- **単一 HTML へ同梱** … engine / ai / view の分離が消える。§2.1〜2.6 の前提が崩れる。→ REJECTED
- **サーバ起動手順を案内する** … 要件そのものの否定。→ REJECTED

## 再発防止（ソース検査）

`node js/engine.js` のセルフテストに番人を足した。**8件**を検査する。

- `js/*.js` に `import` / `export` / `fetch(` が現れたら失敗
- `index.html` に `type="module"` が現れたら失敗
- `index.html` が5本の `<script src>` を読んでいなければ失敗

★ **file:// の破壊は Node のテストでは出ない**（Node は import が通る）ため、
ソース検査でしか捕まえられない。この番人を外さないこと。

## エラーの可視化

致命的エラーで画面が真っ黒になると調査できないため、`index.html` の先頭に
インラインの `window.onerror` / `error`（capture）/ `unhandledrejection` を置き、
画面上部の赤枠（`#fatal`）に出す。**外部ファイルにしない**（その外部ファイル自体が
読めないときに動かなくなるため）。読み込み後にグローバルの有無も点検し、
欠けているファイル名を並べる。

## 検証

Chromium を `file://` で起動して確認（この環境に Windows は無いため **Chromium/Linux** で実施。
遮断していたのは origin 由来の制約で OS に依存しないが、★ Windows Chrome での最終確認は作者側で必要）。

- 人間 vs CPU をシード 1 / 777 / 4242 / 99999 の4本、いずれも**決着まで到達**。
  ドロー・召喚（ピッチ→配置→確定）・攻撃をすべて UI 経由で実行
- CPU vs CPU の「決着まで自動」も決着
- 人間 vs 人間のカーテン（目隠し）も動作
- **console エラー 0件 / pageerror 0件**
- `js/ai.js` を消したコピーでは `#fatal` に「ファイルを読み込めませんでした」が表示された
