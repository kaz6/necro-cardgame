# v0.3 モック1 仕様（2026-10-10）

## 目的（判断の物差し）

1. 将棋のように寝返る体験を、カードゲームっぽくやりたい
2. 寝返った駒を利用してシナジーを生み出す体験を作りたい
3. 一手で状況が一変する体験は残したい
4. 進行の遅いゲーム体験にはしたくない。特に詰めの場面

★ モック1は核だけを確かめる段。能力・キングの軸・チャンピオン・強制移動はモック2以降。

## 盤とキング

- 7×7。列は A〜G、行は 1〜7。先手は行7の側、後手は行1の側
- キングは先手 D7、後手 D1 に置いて始める。それ以外の駒は盤上にない（空の盤から育てる）
- **キングを倒されたら負け。これが唯一の勝利条件**
- キングの動きはチェスのキング（周囲1マス）。キングの強さはデータで指定する（仮の値は下の表）

## 手番

- **1手番に1行動**：盤上の自分の駒を1つ動かす、または手札から駒を1枚置く
- 手番の開始時に、自分の山から1枚引く（仮置き。フラグで「引くこと自体を1行動にする」に切り替えられるようにする）
- 初期手札は3枚。手札の上限はなし
- 試合が200手に達したら引き分け（自動計測の打ち切り用）

## 駒

- モック1の駒は「移動型・強さ・配置範囲」の3つだけを持つ。能力はない
- **移動型は5種。動きの形はチェスと同じで、距離の上限はない**：ポーン（前に1マス進み、取るときだけ斜め前1マス。最初の2マス進みと昇格はなし）、ナイト（8方向に跳ぶ。他の駒を飛び越える）、ルーク（縦横）、ビショップ（斜め）、クイーン（縦横斜め）。ナイト以外は他の駒を飛び越えられない
- 「前」は持ち主から見た向き。寝返ると向きも反転する
- **配置範囲は自陣の奥の列から数える**：0＝最奥列のみ、1＝奥の2列、2＝奥の3列。空きマスにのみ置ける
- 仮の駒構成（両者同じ・山16枚。★ 調整前提の仮の数値）：ポーン 強さ1・範囲2・8枚／ナイト 強さ3・範囲1・3枚／ビショップ 強さ3・範囲1・2枚／ルーク 強さ4・範囲0・2枚／クイーン 強さ5・範囲0・1枚。キング 強さ3

## 戦闘

- 攻撃は、チェスと同じく「動いて敵の駒のマスに入る」こと
- 強さを比べる。**攻撃側が上**なら防御側が倒れ、攻撃側はそのマスに入る。**防御側が上**なら攻撃側が倒れ、防御側はそのまま
- **同値なら両方とも元の持ち主の山へ還る**（山の底へ）。同値のときはドラフトは起きない
- 勝った側の強さが減るかはフラグ（既定：減らない／もう一方：負けた側の強さの分だけ減り、その値は手番をまたいで残る）

## 寝返り

- **倒された駒は、攻撃側・防御側を問わず、倒した側の駒になる。強さは元の値に戻る**（倒された回数が N に達した場合を除く。下記）
- 寝返った駒の置き場所はフラグで切り替える：既定は倒した側のキングの周囲8マス、もう一方は勝った駒の周囲8マス。空きマスの中から倒した側が選ぶ。空きがなければ元の持ち主の山へ還る
- この配置は手番を使わない（1手番1行動の例外）
- **各駒は倒された回数を持つ。N 回目に倒されたときは寝返らず、元の持ち主の山の底へ還る**（N はフラグ。既定 2）
- キングは寝返らない。キングが倒された時点で決着

## 取られた側ドラフト

- 自分の駒を倒された側（寝返り・山へ還る、のどちらでも）は、手番を使わずに自分の山の上から2枚を見て、1枚を自分の手札に、もう1枚を相手の手札に入れる
- 目的はネガティブフィードバック（取られた側への補償）
- 山が1枚なら、その1枚を自分の手札に入れる。山が空なら何もしない
- 駒は「元の持ち主」を覚えておく。相手の手札に渡った駒も、山へ還るときは元の持ち主の山へ

## 測るもの（最優先は決着までの手数）

- 決着までの平均手数、先手の勝率、引き分けの率、盤の埋まり具合、寝返りの回数、山へ還った回数、ドラフトの回数
- 迷っている点（勝った側が減るか、寝返った駒の置き場所）の4通りの組み合わせで比べる

# 以下は v0.2（凍結・参照のみ）

> ステータス: v0.2・基礎ルール確定 ／ 更新: 2026-08-14
>
> 一貫した法則: **自分の手を離れたカードは、すべて相手の資源になる。例外なし。**

## 対戦形式

2人対戦。ターン制。盤面は 3列 × 2段 の6枠。

## ゾーン

- **カードプール**（将来実装）：プレイヤーが事前に選んだカード群
- **デッキ**：プールから作られる山札
- **手札**
- **場**：3×2の6枠。前列と後列
- **墓地**：自分が使える資源置き場

墓地の定義が重要。**自分の墓地に入るのは、①自分が倒した相手のカード ②相手がコスト支払いで捨てたカード の2つだけ。** 自分のカードは、捨てても倒されても必ず相手の墓地へ行く。自分の墓地に自分のカードは存在しない。

## ネクロマンサー

各プレイヤー1枚。専用スロット（6枠とは別）に常時公開で置かれる。出し入れ不可。倒されたら敗北。これが唯一の勝利条件。

**体力は 12**（記載日 2026-08-14。★ **これは実装値の転記であり、設計裁定として決めた値ではない。** CG-017 の測定で分母として現れたためここに控えた。正本は data/cards.js。値を変えるなら裁定として記録すること）

## 初手とドロー

初手は先攻6枚、後攻7枚。**毎ターン3枚ドロー**（更新: 2026-08-12・CG-010 で 2枚 → 3枚）。デッキ切れによる敗北はなし（デッキ枚数は試合の長さの調整弁）。

★ ドロー枚数を上げたのは、ピッチの 1:1 変換（コスト＝捨てる枚数）を変えずに手札の消費感だけを緩めるため。**交換レートは変えていない。** 値は data/cards.js の rules.drawPerTurn。2 に戻せば以前の振る舞いに戻る。

## コスト支払い（ピッチコスト制）

マナは存在しない。カードを場に出すには、**手札からカードを捨てる**。

- 捨てたカードのコスト合計が支払いポイントになる
- そのポイントの範囲内で、**手札または自分の墓地から**カードを出せる
- 1:1変換。コスト5を捨てれば、5を1体でも、4と1でも、1を5体でも出せる
- **捨てたカードは相手の墓地へ行く**
- 出せるのは空き枠のみ

手札と自分の墓地は、召喚元として等価に扱う。

**墓地に入ったカードは、入った直後から召喚できる**（更新: 2026-08-14・CG-016 で確定）。手番のバッファは rules.graveyardSummonBuffer でフラグ化されているが、**既定値は 0（＝制限なし）**。1 は同手番のみ禁止、2 は1手番またぎ。機構そのものは残してあり、デバッグパネルから 0/1/2 を切り替えて比較できる。★ 既定を 0 にした理由は DECISION_LOG「墓地バッファの既定値を 0 に確定する（CG-016）」を参照。墓地にあるのは自分が倒した相手のカードと、相手が支払いで捨てたカードだけなので、**墓地からの召喚は常に「奪ったものを使役する」行為になる**。

## 前列・後列

後列のカードは、同じ列の前列が残っている間は攻撃されない。攻撃は前列・後列どちらからでも可能。配置換えは可能（コストは未確定）。

## 戦闘と死

倒したカードは**自分の墓地**へ入り、以後は自分の資源になる。

## 墓地の総コスト

各プレイヤーの墓地にあるカードのコスト合計を、常時表示する。**プロトでは表示のみで、ゲーム効果は持たせない。** 数値の推移を観測してから、何を紐付けるか決める。

## カード能力（更新: 2026-08-11）

カード8種のうち4種が能力を持つ。**4種とも一貫法則の内側で動き、法則に例外を作らない。**

| id | 数値 | 効果 |
|---|---|---|
| c05 | 2コスト 1/2 | 倒されたとき、1/1 になって後列へ移動する |
| c06 | 3コスト 2/3 | 場に出たとき、右の空き枠に 1/1 のトークンを出す |
| c07 | 4コスト 4/2 | 相手のカードを倒したとき、相手のデッキの一番上1枚を自分の墓地へ送る |
| c08 | 4コスト 2/5 | 呪い。相手の墓地にある間、相手が墓地から召喚する最初の1回に、支払いポイントを1多く必要とする |

**効果テキストに書かれていない部分の裁定**（data/cards.json の rules.abilities でフラグ化）：

- **c05 の後列に空きがない場合は不発。通常どおり相手の墓地へ**（deathRetreatNoRoom）
- **c05 の退避先は同じ列の後列を優先し、埋まっていれば後列を左から**（deathRetreatSlotOrder）
- **c07 は反撃で倒したときも発動する**（killTriggerOnCounterattack）
- **c08 が複数あるときは加算し、その召喚でまとめて全部発動する**（curseStacking）

その他：

- c05 が退避しても「倒された」事実は残る（c07 の効果は乗る）。墓地に入った時点で刷られた数値に戻り、退避権も戻る
- c06 のトークンは data/cards.json の tokens に定義。デッキには入らない。持ち主は出した側。**★ 倒されると相手の墓地へは行かず、その場で消滅する**（更新: 2026-08-11・CG-007。tokens.list[].onDeath）。コスト0のため 0pt で再召喚でき、CPU 同士1000戦で全召喚の 91.7% がこれになって150戦が未決着になったため。**一貫法則の例外ではない**（トークンはカードとして手札に存在しないので、そもそも手札を離れていない）
- c07 がネクロマンサーを倒した場合は勝敗が決するので解決しない
- c08 の「最初の1回」はそのカードが相手の墓地に入ってから数える。墓地から出て入り直せば数え直す
- デッキ構成：c08 は2枚投入。減らした1枚は c07 に回してある（コスト4の総枚数は不変）

- ネクロマンサーが倒された後、使役対象になるか
- 配置換えのコスト
- 小型量産が支配的にならないか（盤面6枠のみを歯止めとして素で測る）
- デッキ枚数
- **盤面が厚くならない件**（CG-006 で AI 由来の可能性は消えた。評価関数ベースの CPU でも平均埋まり率は 28.3% で、ターン6以降はランダムAIと同じ約 2.0/6枠に収束する）
- **~~c06 のトークンをコスト0のまま置くか~~** → **2026-08-11（CG-007）で確定。コストは0のまま、倒されたトークンは消滅する**（tokens.list[].onDeath を vanish）。同じシード帯で測り直し、未決着は 150 → 5 戦、盤面埋まり率は 67.4% → 28.3% になった
- **★ 上の「自分の墓地に自分のカードは存在しない」には例外がある**（CG-006 で判明）。相手に渡ったカードが**相手の場で倒される**と、倒した側＝元の持ち主の墓地へ戻る。一貫法則そのものは保たれているが、「墓地からの召喚は常に奪ったものを使役する行為になる」はこの場合に当てはまらない。表現を直すか仕様を変えるかは裁定待ち
- **~~墓地召喚のバッファの値（CG-011）~~** → **2026-08-14（CG-016）の裁定 A で確定。既定値 0（制限なし）**。ドロー3・バッファ0 で先攻勝率 50.2%、墓地からの召喚 67.7%（500戦・シード 1000〜1499・HEAD 7b71ae3）。バッファ2 は体力寄りの偏りを倍増させ、墓地に欲しいカードがない頻度を 11.5% → 36.0% に増やすため却下
- **★ 先攻1ターン目の攻撃制限を採用するか（CG-017）**。rules.firstPlayerAttacksOnTurn1 でフラグ化済み・既定 true＝従来どおり攻撃できる（ルールはまだ変えていない）。CPU 500戦で先攻勝率 50.2% → 19.1%、1ターン目終了時の後攻ネクロ残体力 2.16/12 → 12.00/12。人間のプレイテストで判断する
- **両者が資源を使い切ったときの決着条件**（手札・デッキ・盤面が空になると endTurn しか合法手が無くなる。デッキ切れ敗北が無いため試合が終わらない）
