## やること
1. 能力2種（運ぶ・投げる）を、モック2と同じく data 側の能力定義として足す
   - engine が能力の名前で分岐しない構造は維持する（CG-023 の方針。発火点と効果の型を足すのはよい）
   - 投げるは新しい「手番の行動」。合法手の一覧に出し、CPU も選べるようにする
   - 運ぶの「右」は持ち主から見た向き（先手：G 列側、後手：A 列側。寝返ると入れ替わる）
2. 前線基地
   - 置けるマスの判定に、仕様の前線基地を加える。毎回盤から計算し、状態としては持たない
   - フラグで切れるようにする（既定：オン）。デバッグパネルで切り替えられるようにする
   - 画面では、前線基地で増えた置き場所が一目で分かるようにする（普段の置き場所と色を分ける）
3. 打つ前に結果を見せる
   - 投げるの着地点・戦闘の勝敗・そこからの押し出しの連鎖と、運ぶで一緒に動く駒を、確定前に盤上で見せる。実際の解決と同じ関数を使う（CG-023 と同じ方針）
4. 駒構成
   - 仕様のモック3の駒構成を data に足す。モック1・モック2も残し、デバッグパネルで切り替える（既定はモック3）
5. CPU
   - 貪欲 CPU は、投げるで勝てる攻撃があればそれも候補に入れる。それ以上に強くはしない（前線基地を狙う、といった戦略は入れない）
6. 自動対戦で測る
   - 貪欲同士・各 500戦・シード 1000〜1499
   - 列：「モック2／モック3」×「キング3・減らない／キング6・減る」の4列。モック3は前線基地オン。加えて、モック3・キング6・減る・**前線基地オフ**の1列
   - 測定の経路が変わっていない確認として、モック2・キング3・減らないの列が CG-023 の数字（平均 24.0 手）と一致すること
   - 指標：CG-023 と同じものに加えて、運ぶ・投げるの発動回数（試合あたり）、投げて戦闘になった回数とその勝率、前線基地が成立した試合の割合と、前線基地に置いた回数、**駒の前進度**（手数ごとに、自陣の奥の3列より前にいる自分の駒の割合。★ 作者が感じた「固めるだけ」を数字で見るための指標）
   - 結果は docs/research 配下に、測定の日時・HEAD・シード帯を添えて書き出す
7. 作者の対戦ログを解析する
   - 作者が 2026-10-12 に遊んだ対戦（人間対貪欲・モック2・シード 1000・97手で作者の勝ち）を engine で再生し、上の「駒の前進度」を作者側・CPU 側それぞれについて出す。ログは作者が別途貼り付けるので、無ければこの項目は飛ばして報告する
8. セルフテスト
   - 運ぶ：右隣がいる／いない、行き先が塞がっている、盤の外、攻撃のときは発動しない、寝返ったら左右が入れ替わる、キングは運ばれない
   - 投げる：空きマスへの着地、敵への着地で戦闘（勝ち・負け・同値）、押し出しを持つ駒を投げて勝ったときの押し出しとその向き、味方・盤の外へは投げられない、キング・不動は投げられない、途中の駒を飛び越える
   - 前線基地：成立・消滅（倒される・寝返る）、フラグオフで効かない
   - 予測と実際の解決の一致を、自動対戦の中で繰り返し検査する。視点フィルタの漏れ検査も続ける
