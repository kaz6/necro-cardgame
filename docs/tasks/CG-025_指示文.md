## やること
1. 発動条件「動かされたとき」「押されたとき」「投げられて着地したとき」を、能力の発火点として足す
   - 用語の定義は仕様の「用語」のとおり。engine が能力の名前で分岐しない構造は維持する（CG-023 以来の方針）
   - 連鎖は決定的に解決する。「1回の連鎖で同じ駒が動くのは1度まで」の打ち切りは、新しい能力すべてに効かせる
2. 能力の変更：運ぶ（改）
   - 攻撃のときも発動。隣の味方から持ち主が1体選ぶ。右隣の縛りはやめる
   - 人間が選ぶ画面の手順を足す（候補が1体なら自動。選ばない、も選べるようにする）。CPU は決め打ちの順番で選ぶ
   - モック3の運ぶ（右隣・攻撃では発動しない）は、モック3の駒構成ではそのまま残す（過去の測定を再現するため）。別の能力定義として足してよい
3. 能力の追加：入れ替え・すり抜け・反動・爆風・道連れ（定義は仕様のとおり）
   - 入れ替えは新しい「手番の行動」。合法手の一覧に出し、CPU も選べるようにする
   - 爆風の「押す順番の決め打ち」は実装側で決め、判断待ちに書き出す
4. 駒構成
   - 仕様のモック4の駒構成を data に足し、既定をモック4にする。モック1〜3は残す
5. 打つ前に結果を見せる
   - 新しい能力の連鎖もすべて、確定前に盤上で見せる。実際の解決と同じ関数を使う
   - 連鎖が長いときに追えるよう、何段目に何が起きたかを順に分かる表示にする（番号や矢印など。形は任せる）
6. 推奨設定ボタン
   - デバッグパネルに「推奨設定」ボタンを足す。押すと「モック4・キング6・勝った側が減る・その他は既定」になる。★ 作者が前回キング10・減らないで遊んでしまい、キングが不死身になったため
   - 既定値そのものは変えない（過去の測定の再現のため）
7. 測定（軽く。★ 面白さは人間が触って決める方針なので、壊れていない確認が主目的）
   - 貪欲同士・各 500戦・シード 1000〜1499。列は「モック3・キング6・減る」（CG-024 の 65.3 手と一致すること）と「モック4・キング6・減る」の2列だけ
   - 指標：平均手数・引き分けの率・駒の前進度、能力ごとの発動回数、**連鎖の長さの分布**（2段以上の連鎖が起きたか）、盤外へ押し出された回数
   - 結果は docs/research 配下に、測定の日時・HEAD・シード帯を添えて書き出す
8. セルフテスト
   - 新しい能力・発動条件ごとに個別に検査する。特に：運ぶ（改）の攻撃時の勝ち・負け・同値、爆風で盤外・衝突・不動・キング、反動の連鎖と打ち切り、道連れで後ろに敵がいる／いない、入れ替えで交換された相手の「動かされた」発動、すり抜けで味方2体や敵は飛び越えられない
   - 予測と実際の解決の一致を自動対戦の中で繰り返し検査する。視点フィルタの漏れ検査も続ける
9. docs の写しを同期する（docs/CURRENT_SPEC.md と docs/SESSION_STATE.md。写し宣言の3点形式は維持）

- 強い CPU、測定の列を増やすこと
